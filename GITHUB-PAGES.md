# Вариант на GitHub Pages

Да, сайт можно разместить на GitHub Pages бесплатно. Но это статический хостинг
без PHP и вне юрисдикции РФ, поэтому он подходит не для всех задач.

## Коротко

| Критерий | GitHub Pages |
|---|---|
| Цена | 0 ₽ |
| Своя статика, HTML/CSS/JS | да |
| Свой домен | да, HTTPS |
| 404, sitemap, robots | да, уже готовы |
| PHP (форма заявки) | **нет** |
| `.htaccess`, серверные редиректы | **нет** |
| Серверы | за пределами РФ (GitHub/Fastly) |
| Подходит для боевого сайта с заявками | с оговорками (см. ниже) |

## Когда GitHub Pages — хороший выбор

- демо для заказчика или портфолио;
- staging-версия перед выкладкой на боевой хостинг;
- сайт-визитка без форм и персональных данных;
- бесплатный хостинг для пет-проекта.

## Когда лучше не использовать

1. **Формы с именем и телефоном.** PHP на Pages нет, значит заявки надо
   отправлять во внешний сервис (Formspree, Getform и т. п.). Это иностранный
   обработчик — с точки зрения 152-ФЗ это трансграничная передача персональных
   данных. Для челябинского бизнеса это лишний юридический риск.
2. **Локальное SEO.** Для Яндекса предпочтительнее свой домен и российская
   площадка. На `username.github.io` сайт выглядит как поддомен чужого сервиса,
   а не как компания в Челябинске.
3. **Скорость из РФ.** Серверы за рубежом: TTFB может быть выше, чем на
   российском хостинге, и доступность не гарантирована.
4. **Серверная логика.** Редиректы, кэш-заголовки, защита от ботов — всё это
   на Pages недоступно или ограничено.

## Бесплатный план

GitHub Pages на бесплатном тарифе публикуется из **публичного** репозитория.
Ограничения: 1 ГБ на сайт, ~100 ГБ трафика в месяц, 10 сборок в час. Для этого
сайта это с большим запасом.

## Как включить (5 шагов)

1. Создать репозиторий на GitHub и запушить проект:
   ```bash
   git init
   git add .
   git commit -m "АэроТех 74: сайт"
   git branch -M main
   git remote add origin git@github.com:USERNAME/REPO.git
   git push -u origin main
   ```
2. Открыть `Settings → Pages` и выбрать **Source: GitHub Actions**.
3. Ничего не редактировать: workflow сам определяет логин и имя репозитория,
   подставляет `SITE` и `BASE` и собирает сайт. Для своего домена достаточно
   добавить переменную `CUSTOM_DOMAIN` в
   `Settings → Secrets and variables → Actions → Variables`.
4. Запушить изменения — workflow соберёт `multi/` и опубликует.
5. Открыть сайт по адресу из раздела Pages.

Локально адрес и префикс задаются переменными окружения:

```bash
SITE=https://USERNAME.github.io/REPO BASE=/REPO python3 multi_src/build.py
```

Пока это тестовая площадка, workflow ставит `NOINDEX=1`: страницы закрыты от
индексации, а `robots.txt` отдаёт `Disallow: /`. При переезде на домен эту
строку нужно убрать.

## Свой домен на Pages

`Settings → Pages → Custom domain` → ввести домен → `Save` → включить
`Enforce HTTPS`.

DNS у регистратора:

- apex-домен (`aerotech74.ru`): A-записи на `185.199.108.153`, `185.199.109.153`,
  `185.199.110.153`, `185.199.111.153`;
- `www`: CNAME на `USERNAME.github.io`.

После подключения домена добавьте переменную репозитория
`CUSTOM_DOMAIN = aerotech74.ru` — workflow соберёт сайт с `SITE=https://aerotech74.ru`
и `BASE=""`, иначе canonical и внутренние ссылки будут вести на github.io.
Не забудьте убрать `NOINDEX=1` из workflow, когда сайт станет боевым.

## Формы, если очень нужно на Pages

| Способ | Плюсы | Минусы |
|---|---|---|
| Formspree / Getform | 5 минут, без кода | данные за рубежом, 152-ФЗ |
| Облачная функция Яндекс Облака | данные в РФ, гибко | нужен аккаунт и настройка |
| Свой мини-сервер под `/send.php` | PHP работает, данные в РФ | нужен VPS/хостинг |
| Отключить формы на демо | 0 ₽, безопасно | нет заявок |

Для боевого сайта разумнее третий вариант: статика на Pages, а форма отправляется
на российский endpoint.

## SEO на Pages

Что работает как есть:

- `sitemap.xml`, `robots.txt`, `404.html`;
- `canonical` и Open Graph — главное, чтобы `SITE` совпадал с реальным адресом;
- ЧПУ с завершающим слэшем — Pages сам отдаёт `index.html` из папок;
- HTTPS и редирект между apex и `www` (настраивается в Pages).

Чего нет:

- `.htaccess` и произвольных 301-редиректов;
- управления кэш-заголовками;
- серверной обработки форм.

Для индексации демо-версии лучше закрыть её: добавить в `head` страниц
`<meta name="robots" content="noindex">` или отдельный `robots.txt` с
`Disallow: /`, чтобы тестовый домен не конкурировал с боевым.

## Гибридный вариант — оптимальный

- **GitHub** — репозиторий, история, ревью и CI;
- **GitHub Actions** — сборка сайта на каждый пуш;
- **Timeweb** — публикация готового `multi/` по SFTP (PHP-форма работает);
- **GitHub Pages** — превью/демо для согласования.

Так вы получаете бесплатный CI и российский хостинг для боевой версии.
Workflow для SFTP-деплоя добавляется отдельным файлом, секреты — в
`Settings → Secrets` (`SFTP_HOST`, `SFTP_USER`, `SFTP_PASSWORD`).

## Итог

- **Демо / портфолио / staging** — да, GitHub Pages удобен и бесплатен.
- **Боевой сайт компании с заявками и SEO** — лучше российский хостинг
  ([HOSTING.md](HOSTING.md)), а GitHub использовать как репозиторий и CI.

Файлы для Pages уже готовы:

- [.github/workflows/pages.yml](.github/workflows/pages.yml) — сборка и деплой;
- генератор поддерживает `SITE` и `BASE` через переменные окружения;
- `multi/` собирается в CI за пару секунд.
